# 管理员指南

本指南用于首次部署和日常管理 Runmesh。默认部署在 Cloudflare Workers 上，Runner 安装在需要执行任务的 Linux、macOS 或 Windows 机器上。

首次初始化不需要额外令牌：直接设置管理员密码，仍校验 CSRF、同源请求、密码确认，并保证只有首个有效提交能成功。未初始化实例对公网开放时存在被先行设置的风险，请先完成初始化。新 Runner 默认 `dedicated_user`，新 MCP 客户端默认 `coding:read`，已有权限不自动修改。当前 `0.1.1` 已作为不可变稳定补丁版发布并完成独立签名资产校验；仓库中的生产配置已精确启用该版本的一键安装分发，默认/开发环境仍保持关闭。参见[修复与上线说明](security-remediation.md)。

## 部署前准备

准备以下内容：

- Cloudflare 账户和一个可访问的 Worker 域名；
- 一个只供管理员使用的强密码（至少 12 个字符）；
- 需要执行任务的机器；
- 明确哪些目录可以被哪些客户端读取、修改或执行命令。

Runmesh 不会替你创建操作系统账号，也不会自动决定工作区权限。请先规划最小权限。

本版本与之前的 Runner、Registry 数据布局是 clean break，不会导入旧表、旧配置、旧服务清单或旧凭据。请为 Durable Object 使用全新命名空间，并为每台机器重新注册当前 Runner；旧部署只能作为单独备份保留。

## 部署控制平面

在 Cloudflare Workers Builds 中连接 GitHub 或 GitLab 仓库，生产分支使用 `dev`，部署命令为：

```sh
npm exec --offline -- wrangler deploy --config apps/worker/wrangler.jsonc --env production --strict
```

在 Cloudflare Variables & Secrets 中配置：

- `ADMIN_TOKEN`：仅供自动化管理 Runner 的高级接口使用；
- `RUNNER_TOKEN_PEPPER`：保护 Runner 凭据校验值；
- `INTERNAL_CONTROL_SECRET`：保护控制平面内部请求；
- `RUNMESH_PUBLIC_ORIGIN`：完整的外部 HTTPS 根地址，不带路径、查询参数或凭据。

`RUNMESH_PUBLIC_ORIGIN` 是配置的规范外部 HTTPS 地址，也适用于反向代理部署。配置该变量后，请求的外部 `Host` 必须与之匹配；新增自定义域名时应同步修改生产环境配置，不会自动授权任意新域名。

请使用密码学安全随机数生成器创建 Secret；`ADMIN_TOKEN`、`RUNNER_TOKEN_PEPPER` 和 `INTERNAL_CONTROL_SECRET` 至少使用 32 字节随机值。三个 Secret 不能提交到 Git 仓库、CI 变量、截图或日志。部署完成后立即打开根地址设置管理员密码，首个完成设置的用户自动成为管理员。初始化采用先到先得；公开实例完成初始化前，请使用 Cloudflare Access 或等效访问控制保护它。

## 添加 Runner

1. 打开「Runner」页面，点击「添加 Runner」；
2. 输入便于识别的显示名称；
3. 选择执行模式。普通场景使用受限服务账号；只有确实需要时才使用高权限模式；
4. 阅读高权限警告并确认；
5. 生成一次性注册码；
6. 复制页面显示的操作系统命令，在目标机器上以管理员权限运行；
7. 返回页面确认 Runner 在线。

添加或重新安装 Runner 时，可以分别填写 Runner 授权和一次性注册码的有效天数。Runner 授权从保存时开始生效，填 `0` 表示永久有效；注册码立即生效且只能使用一次，重新生成会使旧注册码立即失效。不要把注册码写入脚本、工单或聊天记录。Runner 授权过期后，连接和心跳仍可用于恢复，但新的受保护操作会被拒绝；在控制台延长期限后会恢复。

### 安装方式

托管安装器可用时，页面会显示适合 Linux、macOS 或 Windows 的完整命令。命令会固定版本、校验签名、补齐运行环境、完成注册并安装守护服务。

托管安装器不可用时，请按[便携式安装流程](portable-runner-installation.md)先独立验证发布包，再执行 `runmesh enroll --code-stdin`。不要从 npm、分支构建或不明网址下载 Runner。

### 选择权限模式

- **受限服务账号**：适合长期运行。需要管理员明确把工作区目录授权给 Runmesh 服务账号。
- **高权限主机**：以 root、SYSTEM 或等效身份运行。只能用于完全信任的专用机器、虚拟机或容器。

`shell` 不是沙箱。即使工作区策略限制了文件路径，高权限系统账号仍可能访问整个主机。

## 配置工作区

在 Runner 详情页添加工作区：

1. 为工作区设置稳定的名称；
2. 选择绝对路径；
3. 分别勾选读取、修改、命令执行和任务控制；
4. 保存策略并等待 Runner 确认；
5. 使用 MCP 客户端调用 `workspace_list` 验证结果。

工作区根路径只会发送到对应 Runner，不会出现在 MCP 响应、客户端 URL 或普通日志中。修改策略后，Runner 在确认新版本前会拒绝受保护操作。

## 创建 MCP 客户端

1. 打开「MCP 客户端」页面；
2. 输入清晰的标签，例如“团队测试”或“个人开发”；
3. 只勾选需要的能力：读取、修改、执行和任务控制；
4. 创建客户端并复制一次性 MCP 地址；
5. 通过安全渠道交给指定使用者。

地址只显示一次。怀疑泄露时，在客户端详情页轮换或撤销，不要尝试修改地址内容。客户端可以限制可使用的 Runner；多个客户端在同一 Runner 上看到的任务记录属于同一个管理实例。

## 日常运维

- **查看状态**：Dashboard 查看 Runner 在线状态、最近任务和客户端。
- **轮换凭据**：Runner 轮换会使旧凭据失效并断开旧连接；MCP 客户端轮换会生成新地址。
- **撤销 Runner**：阻止重新连接，但不会自动终止主机上已经启动的进程；需要在主机上单独停止进程。
- **删除 Runner**：永久清理该 Runner 的策略、工作区、任务元数据和客户端选择。
- **彻底卸载**：复制注册页面的「移除 Runner」脚本命令，在本机终端或 SSH 中执行。它独立下载维护程序，清理旧版本、安装/配置/状态/日志及服务残留，不依赖旧 Runner 是否完好。会删除本地任务历史，不删除项目工作区；控制台记录需另行删除。详见[卸载说明](runner-uninstall.md)。
- **紧急锁定**：输入 Runner ID 后立即阻止新的受保护操作；随后按需要撤销凭据并检查主机进程。
- **修改管理员密码**：修改后所有已登录的管理会话失效。

## 备份与恢复

Cloudflare Durable Objects 数据需要使用 Cloudflare 提供的备份或导出能力。每台 Runner 还应备份其配置目录、任务元数据、日志、已验证安装包和服务清单。Runmesh 当前不提供应用内一键备份或自动回滚。

升级前先停止或静默 Runner，记录当前版本并在测试环境演练恢复。不要删除 Durable Object 数据来回滚。

## 生产安全清单

- 使用 canonical HTTPS 域名并配置日志脱敏；
- 管理员密码和四个 Worker Secret 分开保存；
- MCP 地址和注册码不进入日志、浏览器共享记录或工单；
- Runner 使用受限服务账号和最小工作区权限；
- 高权限模式只用于专用、可信主机；
- 定期检查在线 Runner、客户端列表和最近任务；
- 为凭据泄露、Runner 被盗和服务失联准备轮换与停机流程。
