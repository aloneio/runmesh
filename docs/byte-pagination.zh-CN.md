# 字节分页与输出可用性

这是 **R07／原计划 P09** 的开发修复批次，基于 `daa7800c256c0143432f5ca105fdd07a3183d179`。源码验证不等于生产部署，不覆盖已发布的 v0.1.3。

本页描述保留兼容的第 1 版／实时读取行为。后续新增的第 2 版显式模式及文件快照、日志代次边界见[绑定游标说明](bound-cursors.zh-CN.md)；普通数字游标不变。

## 修复内容

文件末尾是不完整的 UTF-8 字符时，不再返回不前进的游标。日志遇到同样情况时，不再跳过可能由后续追加补全的字节。最后一页明确表示“不完整”、保留恢复偏移，并停止自动翻页；没有加入后台刷新。

文件页返回前再次检查已打开对象的身份、大小、修改时间及变更时间，并保留原路径与权限检查。日志允许正常追加，但拒绝本次读取中观察到的截短、替换或同大小改写。操作系统短读会在请求缓冲区内继续读取，每个缓冲区最多 32 次；提前读到零字节或用完预算时明确报错。

缺失、访问被拒绝、非普通文件等日志打开错误，不再伪装为成功的空日志。稳定错误码为 `log_unavailable`。日志缺失不能直接认定为过期：也可能尚未创建或被外部删除；排队任务也可能还没有日志。真正的空文件仍返回成功的空页。

命令已经结束后，内嵌 stdout／stderr 读取失败不能抹掉真实 Job ID、状态和退出码。相应输出流使用 `available: false` 与稳定错误码，不回显原始路径和异常，也不建议重跑命令取回日志。直接请求日志则返回结构化读取错误。

## 返回字段

| 字段 | 含义 |
| --- | --- |
| `page_protocol` | 本批新增分页契约版本 `1` |
| `page_state` | `more`：还有可翻页内容；`end`：到达本次观察末尾；`incomplete`：末尾字符未完整 |
| `returned_bytes` | 返回正文的 UTF-8 字节数，不是字符数或 JSON 转义后的大小 |
| `total_bytes` | 本次读取观察到的源大小，不是运行中 Job 的最终输出量 |
| `resume_offset` | 返回完整字符之后的源字节位置，供用户之后显式刷新 |
| `pending_bytes` | 不完整末尾保留的 1—3 字节 |
| `truncated_reason` | 页大小、序列化上限、不完整 UTF-8，或无截断 |
| `snapshot_id` | 固定为空；不把普通数字游标冒充内容快照 |
| `source_truncated` | 日志附加字段，表示已有 Job 级保存截断标记，不代表某个流具体丢失多少字节 |

旧字段和数字游标继续保留。`next_cursor` 只会前进或为空；为空且状态是 `incomplete`，不意味着全部源字节已经交付。来源追加后，用户可用 `resume_offset` 显式读取，不能据此启动自动轮询。源中部的非法 UTF-8 字节仍沿用原有 Node 替换解码行为，本批保证的是有效字符分页及不完整末尾处理。

共享分页元数据由严格 Schema 和跨字段检查约束，未知私密字段不会复制。`read` 目录增加可兼容旧端的输出字段描述；旧端缺少元数据时不编造新字段。没有声称所有工具的输出契约已完整收紧。

## 开销与边界

MCP 文件请求仍限 32 KiB，日志仍限 16 KiB。只读取当前页、最多 3 字节向前补全和最多 7 字节对齐探测，不扫描整份正文。序列化后的日志结果预留空间给 Worker 元数据，避免补上调用回执后把游标挤掉。新增本地元数据检查有 I/O 成本，但没有新增云端写入、必填变量、数据库、心跳或长期定时器。

新 Worker 对旧 Runner 保留原输出；旧 Worker 可能忽略新 Runner 的分页／可用性字段。正式上线应先更新兼容 Worker，再用后续新签名包更新 Runner，不能覆盖既有不可变发布。

本批的单次读取前后检查不是原子快照，也不是文件内容哈希。两次独立请求之间的变更、日志跨页轮转仍需后续的内容绑定／代次绑定游标。搜索、历史、全部工具输出以及完整 P09 验收仍未完成。生产 `main`、服务、凭据和现有发布包本批均不变。
