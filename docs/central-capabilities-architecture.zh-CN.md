## 决策与职责

当前控制端直连的分层约定：`application/connectors/managed-oauth.ts` 负责会话授权、
状态认领、刷新顺序与凭据租约；`contracts/managed-oauth.ts` 定义窄接口，不引用
SDK 或 SQLite 类型。SDK 协议转换、受控 HTTP 与 SQLite 持久化分别由平台适配器
负责，仅在 `capabilities-do.ts` 中组装。架构回归检查阻止用例反向引用适配器、
协议适配器引用存储或加密实现，以及 SDK 类型进入契约。页面渲染只接收展示参数，
不再计算已经移除的部署地址清单和密钥就绪状态。

一个客户端入口将提供三条独立路径：原生 Runner 工具、中央远程 MCP、
中央 Skill 内容。客户端继续负责推理和组合调用。中央查询和内容读取不依赖
所选 Runner，也不要求机器在线，不在每台执行机器重复安装 MCP。

保留原生工具名称、输入输出 schema、目录指纹和 Worker–Runner 协议。
不让中央调用经过 `activeRunnerTool`，不伪装成原生 Job，不把 Skill 存入
Context，也不让原生 Runner 审计包装丢失上游结果类型。

| 边界 | 所有者 | 禁止依赖 |
| --- | --- | --- |
| 身份与机器权限 | 现有 Registry 认证 | 将中央存储变成原生认证的前提 |
| 中央授权规则 | `domain/capabilities`、`application/capabilities` | Runner 选择、具体 SQL、SDK |
| 中央授权持久化 | `platform/capabilities` | Registry 表、Runner 状态、审计回退库 |
| 远程 MCP 适配 | `platform/connectors` | Skill 内部实现、宿主进程执行 |
| Skill 内容 | Skill 领域、应用与平台模块 | 自动执行、权限授予、Runner Context |
| 对外 provider | `mcp/providers` 薄适配器 | 应用实现类、存储、凭据池 |
| 装配 | HTTP 与入口层 | 复制第二套授权规则 |

接口放在 `contracts/`，由装配层注入小接口；不引入通用依赖注入框架，
也不引入万能插件执行器。功能域内部实现不能互相导入，原生模块只能通过
明确的装配点引入中央实现。

## 可执行的解耦规则

`scripts/central-architecture-policy.mjs` 叠加于既有分层和运行时／类型环检查。
Connector 与 Skill 不得互相导入内部实现；纯规则不能引入 SDK、Worker 环境类型、
存储实现或 Runner 通信包。未经审核的中央顶层目录被拒绝，即使文件没有 import。

AST 检查还拒绝纯中央契约／规则直接访问平台 I/O 全局对象，以及中央模块直接
动态执行代码。这些是保守的可维护性门禁，不是操作系统沙箱，也不是对任意混淆
代码的安全证明。测试同时包含违规依赖和合法的装配／端口路径。

## 身份版本化，不自动授权

v2 `ClientIdentity` 将 `native_scopes` 与凭据身份分开。空机器权限只在明确的
v2 主体中有效，不代表获得任何中央工具、Skill 或机器权限。

认证仍使用同一份凭据记录和底层实现。旧非空 scope 数组保持原行为；v2 在原有
scope 列保存 `{schema_version: 2, native_scopes: [...]}`，格式损坏、未知版本和
非预期持久化字段一律拒绝。没有迁移或重置核心 namespace、表或凭据。

内部创建与验证接口显式接受 `identity_version: 2`；旧创建接口仍拒绝空权限。
v2 验证投影供既有 MCP 入口使用，不改变原生工具 schema。轮换、撤销、凭据代次
约束适用于两种格式。原生 RPC 授权链保持不变，空机器权限不能执行机器操作。
W08 新增独立的[中央管理界面](central-administration.zh-CN.md)。

**回退边界：**旧 Worker 不理解 v2 持久化主体对象，会拒绝这些新主体；旧客户端
仍可继续使用。不能宣称新 v2 主体兼容旧代码回退，也不能通过清库或静默赋予
机器权限来恢复它们。

## 中央授权和可选状态

授权精确绑定客户端、资源类型、稳定资源 ID 和已批准内容摘要；远程工具还绑定
连接档案 ID。不支持通配符，不从 coding scopes、Skill 文本或工具风险提示推导权限。

`createCapabilityAccess` 有界读取身份和授权，并在独立授权库读取后再次检查身份。
返回值只是当前观察，不是可长期复用的派发凭证。后续调用实现必须在排队／连接
等待后重新校验身份和授权版本；不能承诺跨所有者事务或撤销在途副作用。

`CapabilitiesDOv1` 现在由 `capabilities-do.ts` 承担经过审核的中央装配职责，
没有公开的 DO fetch API。Worker 另外提供受保护的管理 JSON 入口；各领域仓储
仍不互相导入。仓储负责惰性、原子
建表与版本检查写入；未知、残缺或外来状态不会被清空。并发修改必须携带观察到的
版本；停用保留记录并增加版本，而不是删除历史。

Wrangler 的 **test 和 development 环境**绑定该类。development 增加独立的
central-dev-v1 SQLite 迁移，保留原 Registry 和 Runner 身份。生产绑定和必填秘密
不变。原生工具调用不解析中央状态绑定或读取凭据密钥；已启用的中央发现检查实时
身份和授权，故障时保留原生目录。关闭的授权工厂不解析端口，也不创建定时器。

W03 已加入 bearer 凭据后端：版本化连接档案、AES-256-GCM 加密封装、有界密钥环、
仅存密文的仓储，以及受保护的档案管理。WebCrypto 限定在 Connector 适配器内，
应用逻辑通过窄接口使用授权、加密与存储。调用适配器通过专用端口使用凭据，
没有明文读取 API 或自动配置密钥的功能。W06 的独立 OAuth 适配见
[OAuth 指南](central-oauth.zh-CN.md)。

管理路径为 `/admin/central/profiles/{profile_id}`。GET 返回安全元数据；POST 只接受
创建、轮换、启用、停用和重新加密命令。必须具有管理员会话、同源请求和相匹配的
CSRF 请求头与 Cookie，不允许用 ADMIN_TOKEN 绕过。请求体读取后重新检查会话，
加密等待后由状态所有者再次验证，随后立即进行同步、版本检查的写入。
未知或损坏回执不能变成成功结果，也不能把任意字段拼进错误信息；派发后超时按结果未知处理。

新档案默认停用，轮换不能修改 Connector 身份或目标地址。密文认证信息绑定实例
namespace、档案、Connector、目标地址、秘密代次和密钥 ID，每次加密使用新的随机 IV。
SQLite 只保存密文和元数据。导入后的密钥不可导出，临时字节数组会清零；JavaScript
字符串不能可靠清零。该设计保护持久化值，不声称能够对抗已经失陷的 Worker 运行环境。

密钥轮换流程为：向 CENTRAL_VAULT_KEYRING 添加独立的新随机密钥，选为活动密钥，
显式重新加密档案，并在所有引用均已验证前保留旧密钥。重新加密会增加秘密代次；
启用／停用无需解密，在密钥不可用时仍能停用。提前删除旧密钥会导致尚未迁移的密文
不可读，不能回退使用控制面秘密、假值或自动重写数据。本次开发没有更改线上密钥。
实现依据为 Cloudflare WebCrypto 和 Worker secrets 官方文档。

档案 URL 当前只校验无凭据 HTTPS 语法和规范化后的大小，不代表完成 DNS／SSRF
防护。W03 不向上游发送请求；真正调用上游前，仍须实现经过审核的出站访问适配器
和中央能力授权检查。

## 已强制执行的初始预算

| 项目 | 上限 | 执行位置 |
| --- | --- | --- |
| 持久化机器权限表示 | 1,024 字符 | 身份解码 |
| 每客户端授权规则 | 128 条 | 授权解析 |
| 编码后授权记录 | 65,536 字节 | 授权解析和持久化读取 |
| 每状态所有者授权记录 | 1,000 条 | 新建准入；已存在记录仍可停用 |
| 单次授权观察 | 5,000 毫秒 | 可取消的请求级截止时间，无周期定时器 |
| 每所有者连接档案 | 1,000 条 | 新建准入；已有档案仍可停用 |
| Bearer 凭据 | 4,096 ASCII 字节 | 封闭的 token 语法，拒绝请求头注入 |
| 管理命令请求体 | 16,384 字节 | 解析前的流式大小限制 |
| 密钥环 | 4 个密钥／4,096 字符 | 独立的版本化密钥，不复用控制面秘密 |
| 档案操作 | 5,000 毫秒 | 每次异步等待后重新检查截止时间 |

这些是初始安全上限，不是经过实测的生产容量承诺。上游发现、schema 复杂度、
返回字节、连接并发和 Skill bundle 预算由对应 W04/W05/W07 模块执行。
审计失败不能成为自动重放写操作或保存秘密的理由。
