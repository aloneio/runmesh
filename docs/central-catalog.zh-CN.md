# 中央工具目录审核（开发版）

W05 可选实时发现／调用适配器及其明确限制见[受控中央 HTTP MCP](central-remote-mcp.zh-CN.md)。
本文介绍可独立使用的目录审核与快照流程。

[English](central-catalog.md)

**状态：dev 上的 W04 目录基础，中央存储仍仅绑定 test 环境。**
本批次加入手动导入目录、不可变快照、已审核工具选择和按权限过滤的内部读取。
它不是已经启用的 MCP 代理，不进行远程发现／调用，不安装 Skill，也不改变原生
MCP 工具目录。

## 审核流程

先通过 W03 管理接口建立连接档案，其 ID、Connector ID 和目标地址共同绑定目录。
连接处于停用状态时仍可审核目录，但不会向客户端提供工具。

POST `/admin/central/catalogs/{profile_id}` 必须带管理员会话、同源请求和匹配的
CSRF Cookie／`x-csrf-token` 请求头。不要把秘密放进工具说明或 schema：这些描述
属于可被授权读取的内容，不是加密凭据库。

| 操作 | 请求 | 效果 |
| --- | --- | --- |
| 导入完整目录 | `{"action":"stage","expected_revision":0,"tools":[...]}` | 保存最新导入，不自动批准 |
| 查看当前审核状态 | GET，无查询参数 | 返回当前版本、导入快照与差异摘要 |
| 查看保留的快照 | GET，`?snapshot=<digest>` | 读取同一档案下的固定版本 |
| 批准指定工具 | `{"action":"approve","expected_revision":1,"digest":"<digest>","tool_names":["search"]}` | 只批准最新导入中的指定工具 |
| 停用目录 | `{"action":"disable","expected_revision":2}` | 清除已批准选择，不删除快照 |

成功修改会增加目录版本；过期版本返回冲突，不覆盖其他人的审核。重复导入完全
相同的目录会复用快照正文，但仍增加观察版本。目录读取不会逐项联网，也不创建
隐藏的原生 Job。

导入内容是管理员提供的资料，**不是已验证的实时上游响应**。W05 的安全 HTTP
发现适配器还需接入同一生命周期。上游连接失败不能被转换为空目录；只有明确
导入的空数组才表示空目录，并隔离之前存在的工具。

## 稳定身份与变更处理

工具 ID 对档案、Connector、目标地址和上游工具名进行完整 SHA-256 摘要。
公开名称包含有界的可读前缀和完整摘要，限制在 128 个允许的 ASCII 字符内；
不会把上游服务显示名称当作唯一身份。元数据变化保留公开名称，但改变工具内容
版本和快照摘要。

标题、描述、已接受的输入输出 schema 和注解均纳入摘要。风险注解是不可信提示，
不是权限。属性顺序和上游工具排列会规范化，但不会打乱 schema 内数组的语义。
不支持的描述字段会拒绝，而不是静默删除。

已批准选择与最新导入分开保存。最新导入中变更或移除的工具，会立即从旧批准视图
排除；未变化且已选择的工具仍可见。新增或变更工具需要重新审核，并取得对应新
内容版本的客户端授权。批准目录不会修改客户端授权。恢复旧快照需要明确重新导入
和审核，不代表真实上游已回滚。

本阶段的共享工具选择以**单个连接档案**为边界，尚未实现跨多个连接的独立命名
ToolsetProfile。后续分组功能应与目录完整性和执行权限保持独立。

## schema 支持边界

初始元数据子集采用 JSON Schema 2020-12，可显式声明或使用默认版本。输入必须
以 object 为根，输出可描述其他 JSON 类型。支持基本类型、属性、必填字段、
枚举／常量、数值／大小限制、组合、条件、局部定义和无环局部引用。普通属性名及
default／examples 数据不会被误当成 schema 指令。

暂不支持正则 pattern／patternProperties、format、外部或递归引用、动态引用、
ID／anchor、自定义参数请求头、未知关键字或其他方言，也暂不导入 icons 和任意
`_meta`。这会明确拒绝部分符合更广 MCP 标准的定义，不会转换为更弱的 schema。
W04 校验元数据结构和预算，**不实现运行时参数求值器**；W05 开放调用前必须补齐
并验证承诺子集的参数校验。

## 客户端目录读取

内部 `listCatalog(principal, query)` 检查当前凭据代次和中央授权，不需要 Runner，
也不把 coding scopes 视为中央权限。可见工具是“已批准选择、最新导入中未变化的
工具、客户端精确授权”三者的交集。

每次查询一个档案，最多返回 20 个工具。先过滤权限再分页，不泄露隐藏工具及其
数量。HMAC 游标绑定状态所有者、客户端／凭据代次、连接档案／版本、授权版本、
目录版本、分页大小和五分钟有效期。异步等待后再次检查身份与状态；游标不是授权凭证。

本批次没有修改 MCP `tools/list` 注册。后续远程 provider 应复用同一个目录读取
用例，不复制第二套策略。当前普通 Runmesh 客户端仍获得原生工具目录。

## 存储、预算与恢复

目录表在可选中央所有者内拥有独立版本标记，快照正文不可变。快照插入和当前指针
更新在同一事务内完成；更新失败不能留下已发布或孤立的新快照。未知或不完整的
schema 状态会拒绝，不清库恢复。不向目录表复制凭据、完整调用参数、Runner 状态
或远程执行结果。

| 初始上限 | 数值 |
| --- | --- |
| 每档案工具数 | 128 |
| 单个工具定义 | 32 KiB |
| 导入请求／单份快照 | 各 512 KiB |
| JSON 深度／节点 | 16／8,192 |
| schema 节点／包含深度 | 2,048／12 |
| 档案数／快照总数 | 200／512 |
| 每档案保留版本 | 32 |
| 快照正文总存储 | 16 MiB |
| 分页工具数／游标大小／有效期 | 20／2 KiB／5 分钟 |

超限不自动删除已审核内容，已有目录仍可停用。这些是安全上限，不是实测的生产
吞吐承诺。100 个档案、2,000 个工具的测试是本地模拟目录样本，不代表已连接
100 个真实 MCP 或完成生产压测。

生产／开发部署绑定、Runner 代码、Worker–Runner 通信契约和原生工具定义均保持
不变。缺少可选绑定时，不解析中央存储或凭据端口。本地测试不代替真实宿主目录
刷新与旧调用链问题的验收。
