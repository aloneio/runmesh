# MCP 工具目录实现

[English](central-catalog.md) · [维护者文档](maintainers/README.zh-CN.md)

本文介绍目录管理接口、快照存储和 schema 校验。
通过控制端连接 MCP、刷新工具时，按[MCP 和 Skill 指南](central-administration.zh-CN.md)操作。
实时发现与调用的实现见[HTTP MCP 实现](maintainers/central-remote-mcp.zh-CN.md)。

所有凭据有效的客户端共享已启用且发布的工具。控制端输入 MCP URL，选择无认证
或 OAuth，连接成功即原子发布全部工具。本文介绍其底层快照契约。

## 快照管理

先通过[管理接口](maintainers/central-administration.zh-CN.md)建立连接档案，其 ID、Connector ID 和目标地址共同绑定目录。
连接处于停用状态时仍可审核目录，但不会向客户端提供工具。

POST `/admin/central/catalogs/{profile_id}` 必须带管理员会话、同源请求和匹配的
CSRF Cookie／`x-csrf-token` 请求头。工具说明和 schema 会分享给获授权的读取者；
账号凭据请通过连接的认证设置保存。

| 操作 | 请求 | 效果 |
| --- | --- | --- |
| 原子发布全部工具 | `{"action":"publish","expected_revision":0,"tools":[...]}` | 一次保存并发布完整目录；实时发现使用此操作 |
| 导入完整目录 | `{"action":"stage","expected_revision":0,"tools":[...]}` | 保存最新导入，不自动批准 |
| 查看当前审核状态 | GET，无查询参数 | 返回当前版本、导入快照与差异摘要 |
| 查看保留的快照 | GET，`?snapshot=<digest>` | 读取同一档案下的固定版本 |
| 批准指定工具 | `{"action":"approve","expected_revision":1,"digest":"<digest>","tool_names":["search"]}` | 只批准最新导入中的指定工具 |
| 停用目录 | `{"action":"disable","expected_revision":2}` | 清除已批准选择，不删除快照 |

成功修改会增加目录版本；过期版本返回冲突，不覆盖其他人的审核。重复导入完全
相同的目录会复用快照正文，但仍增加观察版本。目录读取不会逐项联网，也不创建
隐藏的原生 Job。

手动导入记录管理员提供的定义；实时发现记录上游响应并原子发布，连接失败时保留
已有目录。明确导入空数组表示空目录，并隔离之前存在的工具。

## 稳定身份与变更处理

工具 ID 对档案、Connector、目标地址和上游工具名进行完整 SHA-256 摘要。
公开名称包含有界的可读前缀和完整摘要，限制在 128 个允许的 ASCII 字符内；
不会把上游服务显示名称当作唯一身份。元数据变化保留公开名称，但改变工具内容
版本和快照摘要。

标题、描述、已接受的输入输出 schema 和注解均纳入摘要。注解提供提示，执行权限
单独检查。属性顺序和上游工具排列会规范化，schema 内数组保留原有顺序。工具定义
接收 `name`、`title`、`description`、`inputSchema`、`outputSchema` 和
`annotations`；包含其他描述字段时，整份目录校验失败。

实时发现把完整快照和全部工具名一次性发布；空目录同样原子生效。底层手动导入接口
仍可把已批准选择与最新导入分开保存。最新导入中变更或移除的工具，会立即从旧批准视图
排除；未变化且已选择的工具仍可见。实时刷新后新增或变更工具自动向所有有效客户端发布，手动快照导入可使用 stage/approve 分步保存与发布。恢复旧快照需要明确重新导入
和审核，不代表真实上游已回滚。

共享工具选择按连接档案发布。旧逐客户端授权和工具集分配已退役，不参与实时读取或调用。

## schema 支持边界

工具描述允许有界服务方注解；快照仍使用严格字段、排序及内容派生身份。
支持常见 JSON Schema 方言及 OpenAPI 形式，保留参数和输出约束，不加载外部引用或执行代码。
未知注解不授予权限。不支持的正则、递归图和必需的未知 vocabulary 会阻止对应工具执行，
而不是删除约束。发现时隔离并返回明确诊断；非空目录没有可支持工具时保留旧目录。
详见 [MCP 兼容性矩阵](mcp-compatibility.zh-CN.md)。

## 共享目录读取

listCatalog 检查当前凭据代次，返回已批准选择与最新观察中未变化定义的交集；
不需要 Runner、原生 scope 或逐客户端授权。

每次查询一个档案，先按发布状态过滤，再分页，每页最多 20 个工具。v2 HMAC 游标
绑定状态所有者、客户端及凭据代次、连接档案及版本、目录版本、分页大小与五分钟
有效期。旧 v1 游标拒绝并要求刷新。异步等待后再次校验身份与发布；游标不是授权凭据。

`remote_profiles` 列出共享服务；`remote_search` 搜索已发布工具的名称、标题、
说明和连接名称；`remote_tools` 分页列出完整工具定义。搜索接收 `query`、
可选的 `profile_id` 和 `limit`（默认 10，最多 20）；查询最多 256 个 UTF-8 字节。
搜索读取已保存快照，返回前再次校验身份与发布状态，不请求上游服务。结果包含
调用 `remote_call` 所需的确切 `tool_id` 和 `version`；调用前用 `remote_tools`
读取输入 schema。小目录还提供 rm_ 直接别名；大目录使用有界发现接口，
无需用户手填内部档案 ID。

## 存储、预算与恢复

目录表在可选中央所有者内拥有独立版本标记，快照正文不可变。快照插入和当前指针
更新在同一事务内完成；更新失败不能留下已发布或孤立的新快照。未知或不完整的
schema 状态会拒绝，不清库恢复。不向目录表复制凭据、完整调用参数、Runner 状态
或远程执行结果。

| 初始上限 | 数值 |
| --- | --- |
| 每档案工具数 | 512 |
| 单个工具定义 | 64 KiB |
| 导入请求／单份快照 | 各 2 MiB |
| JSON 深度／节点 | 32／32,768 |
| schema 节点／包含深度 | 4,096／16 |
| 档案数／快照总数 | 200／512 |
| 每档案保留版本 | 32 |
| 快照正文总存储 | 16 MiB |
| 分页工具数／游标大小／有效期 | 20／2 KiB／5 分钟 |

新快照需要容量时，存储会优先回收最旧且已不再被当前观察或批准版本引用的快照；
先满足该档案的版本上限，再满足共享数量和字节上限。回收与发布在同一事务内完成；
无法预留足够空间时，写入失败且不删除已有快照。当前观察和批准版本保持受保护，
已有目录仍可停用。因此，保留的目录历史是有界记录，并非永久档案。

上表规定准入和存储限额；本地目录
测试使用 100 个模拟档案、2,000 个工具。吞吐量和实际 MCP 连接容量需在目标环境测量。

中央功能启用时解析目录存储和凭据端口。发版验收时，按[中央功能验收清单](central-rollout.zh-CN.md)
使用真实 MCP 客户端验证目录刷新与调用。
