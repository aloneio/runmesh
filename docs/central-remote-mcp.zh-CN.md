# 连接 MCP

[English](central-remote-mcp.md) · [MCP 和 Skill 指南](central-administration.zh-CN.md)

在控制端添加一次 MCP，即可通过已连接的 AI 客户端使用其启用的工具。

## 添加连接

1. 打开「MCP 和 Skill → MCP」。
2. 在「MCP 地址」中粘贴提供方的公网 HTTPS MCP 端点，例如 `https://mcp.example.com/mcp`。
3. 公开 MCP 选择「无身份验证」，需要账号登录的 MCP 选择「OAuth」。
4. 按需填写名称，点击「连接」。名称留空时会使用主机名。
5. 选择 OAuth 后，在提供方页面完成登录与授权，Runmesh 会返回控制端并加载工具。

使用标准 HTTPS 端口上的直接端点，地址包含主机名与 MCP 路径，账号凭据通过 OAuth 流程管理。提供方给出下载页或配置页时，请从其连接说明中获取 MCP 端点。

OAuth 提供方可采用客户端元数据文档或自动客户端注册；要求预先注册 OAuth 应用的提供方可使用连接表单中的可选「OAuth 客户端设置」。登录步骤见[MCP 账号授权](central-oauth.zh-CN.md)。

## 检查连接

连接检查、`server.json` 导入和 `remote_search` 由 0.1.8 及后续兼容版本的控制端提供。部署渠道见[发行状态](release-readiness.zh-CN.md)。

填写 MCP 地址后点击「检查连接」，查看协商的协议版本、工具数量及服务声明的能力。也可在已启用 MCP 的卡片上检查连接。需要登录时，新连接选择「OAuth → 连接」，已有连接点击卡片上的「重新授权」。

检查会读取连接信息。准备好后，点击「连接」添加 MCP，或用「刷新工具」更新已有 MCP 共享的工具列表。

Runmesh 将上游 HTTP `401` 视为身份验证挑战，并可能要求重新授权；上游 HTTP `403` 则表示提供方已接收凭据但拒绝 MCP 访问。此时 Runmesh 会报告提供方权限错误，而不是再次启动 OAuth 循环。请检查提供方是否为当前账号开放 MCP，以及相关群组或项目权限。

## 导入 MCP JSON 配置

展开「导入 MCP JSON 配置」，选择 JSON 文件，点击「预览连接」。支持 MCP Registry 的 `server.json`（包括 `server` 包装对象），以及客户端 `mcpServers`、`servers` 或 `mcp.servers` 配置。对于公网 HTTPS 条目，点击「使用此连接」填入普通连接表单，选择身份验证方式后点击「连接」。

客户端 `http` 和 `streamable-http` 条目可预览为直接远程连接候选；旧式 SSE 需要另外配置。本地 `stdio` 条目（`command` / `args`，包括 `npx`）**不会被执行或安装**，请向服务方获取托管的 HTTPS MCP 地址。自定义请求头、私有端点和 URL 模板不会自动连接。RunMesh 当前支持公开 MCP 和托管 OAuth，不支持任意 API Key 请求头。

浏览器会在发送预览请求**之前**移除命令参数、环境变量值、请求头值与密钥。Worker 只返回投影后的连接元数据，并基于脱敏投影计算预览摘要。客户端预览会排除含凭据或查询参数的 URL。预览不会保存或启用连接，也不会发布工具；Registry 软件包仍只用于展示。

## 使用和刷新工具

点击 MCP 卡片的「查看工具」，即可浏览工具名称与说明。已启用的工具共享给实例中的有效 AI 客户端；客户端接入方法见[用户指南](user-guide.zh-CN.md)。

提供方更新工具后，点击「刷新工具」。RunMesh 会自动发布全部兼容工具（包括新增或变更定义），不需要逐项审核或批准。此前暂存待审核、仅部分批准的目录也会通过同一次刷新自动更新。已完整发布且内容未变化时，不会创建新版本；刷新失败会保留原目录。

如果发现工具期间目录版本发生变化，RunMesh 会验证最新目录是否完整发布，再最多重新读取一次上游 `tools/list`。恢复成功时，接口返回 `recovered_from_revision`。如果新目录已停用、待发布或部分批准，连接授权发生变化，或再次发生冲突，则停止自动恢复并报告冲突；此时请重新查看工具列表。该机制不会重新执行 `remote_call` 或任何提供方操作。

工具较少时，Runmesh 会直接列出工具；较大的工具集合可通过目录工具浏览。AI 客户端可用 `remote_profiles` 查找 MCP，用 `remote_search` 按关键词搜索，用 `remote_tools` 读取完整工具定义，再以返回的工具 ID 和版本调用 `remote_call`。搜索会匹配工具名称、标题、说明及连接名称，添加 `profile_id` 可限定到一个 MCP。添加或修改连接后，请刷新客户端的工具目录。

## 暂停和恢复

「暂停」停止所有客户端对该 MCP 工具的访问，并保留连接设置；「启用」恢复共享并重新加载工具。OAuth MCP 在暂停与恢复期间保留账号连接，「断开账号连接」则移除保存在 Runmesh 中的账号连接。详见[授权指南](central-oauth.zh-CN.md)。

## 连接格式与大小

Runmesh 通过 Streamable HTTP 连接公网 HTTPS MCP 端点，读取 JSON 或单次请求内的 SSE 响应，并向客户端返回文本、图片、音频、资源和结构化结果。每次调用使用独立的上游会话。

| 项目 | 上限 |
| --- | --- |
| 完整工具目录 | 512 个工具 |
| 发出的单次请求 | 64 KiB |
| 单次上游响应 | 2 MiB |
| 一次操作中的上游响应总量 | 8 MiB |
| 返回的内容项 | 128 项 |
| 操作时间 | 20 秒 |

输出较大时，请使用提供方的分页或筛选工具。调用发出后超时，先在提供方核对结果，再决定是否重复执行会修改数据的操作。

遇到错误时见[故障排查](troubleshooting.zh-CN.md)。协议与部署细节见[传输参考](maintainers/central-remote-mcp.zh-CN.md)。

## 部分工具兼容

首次发现及后续刷新都会自动发布兼容工具，同时提示不支持的 Schema 或必需交互；这不是 OAuth 失败。
全部工具不可支持时保留原目录。详见 [兼容性矩阵](mcp-compatibility.zh-CN.md)。
