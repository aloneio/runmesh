# 部署 MCP 连接与 Skill

[English](central-rollout.md) · [管理员指南](admin-guide.zh-CN.md) · [升级指南](upgrading.zh-CN.md)

按以下步骤为已有 Runmesh 实例添加共享 MCP 连接与 Skill，并在用户实际使用的 AI 客户端中验证完整流程。

## 准备实例

1. 从[发行状态](release-readiness.zh-CN.md)选择控制端版本，阅读对应的[版本说明](release-notes.zh-CN.md)。
2. 备份部署配置与保留的数据，继续使用现有 Worker、Registry、Runner、Capabilities 资源、D1 绑定和部署密钥。
3. 通过现有生产部署路径更新，按[构建来源](build-provenance.zh-CN.md)核对运行中的提交与环境。

OAuth 连接使用现有 `INTERNAL_CONTROL_SECRET`，Runner 凭据使用 `RUNNER_TOKEN_PEPPER`。升级时保留这两个值，使已有账号连接和已注册计算机继续工作。新实例的初始化方法见[运行时配置](runtime-config.zh-CN.md)。

## 连接服务并安装 Skill

1. 打开「MCP 和 Skill → MCP」，填写提供方的公网 HTTPS 端点并选择身份验证方式。按[连接 MCP](central-remote-mcp.zh-CN.md)操作；使用 OAuth 时完成提供方的登录授权。
2. 打开已保存连接的工具列表，确认需要的工具已经加载。
3. 打开「MCP 和 Skill → Skill」，安装包含 `SKILL.md` 和配套文本资料的文件夹，再查看安装后的文件。详见[安装与更新 Skill](central-skills.zh-CN.md)。
4. 创建客户端连接，设置使用者需要的访问范围，将创建时显示的 MCP 地址添加到其 AI 客户端。

客户端连接可以直接使用共享工具和 Skill。需要读取文件或执行主机命令时，再启用计算机访问，并为 Runner 配置获准的工作区。

## 验证完整流程

为实际使用的各个 AI 客户端分配独立凭据。刷新 Runmesh 工具与资源列表，然后完成以下检查：

| 检查 | 预期结果 |
| --- | --- |
| 读取 Skill 与一个配套文件 | 两次读取使用选定的同一 Skill 版本。 |
| 调用无副作用的提供方工具 | 客户端收到提供方的结果。 |
| 更新 Skill 或刷新提供方工具 | 刷新后的客户端能看到选定版本和当前工具目录。 |
| 暂停并重新启用连接 | 工具访问随连接状态变化。 |
| 轮换测试客户端凭据 | 新地址正常工作，旧地址返回凭据拒绝结果。 |
| 访问已批准的 Runner 工作区 | 文件读取和简单测试命令遵循配置的权限。 |
| 跟踪测试命令 | 使用原 Job ID 和工作区 ID 取得任务状态与保留日志。 |

日常流程涉及长任务、输入或取消时，也在测试工作区验证这些操作。记录组件版本、提供方与客户端名称、测试时间和结果，便于后续升级重复检查。

## 观察运行与恢复

扩大使用范围前，用有代表性的流量观察响应时间和 Cloudflare 用量。按[资源用量测量（英文）](cost-baseline.md)在相同时间范围内比较存储、CPU 和请求数量。

提供方需要处理时，查看对应卡片，刷新工具或完成登录。调用超时后，先在提供方核对执行结果，再决定是否重复修改操作。跟进 Runner 任务时保留原 Job ID。各组件的处理步骤见[故障排查](troubleshooting.zh-CN.md)。

升级后需要恢复旧版本时，按演练方案一起恢复匹配的程序、配置和数据，沿用现有密钥与注册身份。按照[升级指南](upgrading.zh-CN.md)操作，完成相同的流程检查后再按备份策略处理旧副本。
