# Context 容量与显式保留清理

使用 `context` 查看工作区 Context 用量，并预览、清理旧版本。这些动作已在 **0.1.4 候选版**中实现，需要兼容的 Worker 和 Runner。已发布的 v0.1.3 Runner 不支持这些动作；更新 Worker 不会自动升级已安装的 Runner。

## 工作区容量限制

新增检查点会在超过容量限制时被拒绝，不会删除或隐藏已有上下文来腾出空间。上下文数量超过索引上限时，重建也会拒绝生成不完整的索引。

每个工作区默认上限为：版本文件的逻辑字节 **32 MiB**、版本文件 **4,096 个**、上下文目录 **256 个**。索引另有 2 MiB 上限，意图文件和临时索引有额外有界开销。这里不是文件系统实际分配块、剩余磁盘保证，也不是整台主机所有工作区的总配额。嵌入式使用可以降低这些限制，不能无限提高或关闭；没有新增部署必填变量。

真正新增版本前才进行有界元数据盘点；完全重复的有效请求先返回原回执，因此满额不会让正常去重重试失败。旧的超额数据不自动清理或改写。未知文件、链接和不安全目录会阻止新写入或清理，不能当成可随手删除的垃圾。

## 只读查看用量

调用 `context` 工具，使用 `action=storage` 和 `workspace_id`。需要当前 `coding:read` scope 与工作区读取权限。返回文件数、逻辑字节、上下文数、元数据字节、限制、是否超额及是否有未完成检查点；不返回绝对路径、正文或环境变量。

盘点仅扫描两层元数据，上限为 16,384 个目录项、8,192 个版本文件和 1,024 个目录，并在扫描步骤之间检查四秒预算；这不能中断单次操作系统 I/O。较高的盘点边界用于诊断部分历史超额状态；超限返回 `context_scan_budget`，不会把部分统计作为完整结果。`bootstrap/read/search` 保留定向读取；读取和预览不会建目录或重写索引。文件系统正常更新访问时间不属于接口的持久化写入。

## 清理先预览，再显式执行

示例先只生成预览：

```json
{"action":"prune","workspace_id":"workspace","keep_days":30,"keep_revisions":2}
```

预览与执行都要求 `coding:write` 和工作区编辑权限。一个旧版本必须同时满足“记录中的更新时间早于保留天数”和“不在最近指定数量的现存版本中”才可被选中。**每个上下文最新版本始终保留。**这些参数只针对当前调用，不会保存成自动清理策略。

预览返回清单哈希、候选数量／字节、仍保留的上下文数和扫描量。它会检查记录指纹、文件名、索引与最新版本关系；损坏或存在未恢复检查点时拒绝清理。预览没有正文，也不会自动执行。

审阅后，用相同参数加 `apply=true` 和返回的 `expected_plan_hash` 才执行。每批最多 128 个旧版本，可用 `max_delete` 降低。存在更多候选时返回 `has_more`，下一批仍必须重新预览和明确执行，不自动循环。

清单绑定工作区、策略代次、参数、库存文件身份和候选正文哈希。文件、新检查点或策略发生变化后拒绝旧清单。每次删除前重验候选文件、受保护的最新版本、目录链及当前授权。哈希不是授权，也不能把操作系统文件访问变成原子事务。

## 清理中断后的处理

清理不改最新记录和索引，每个旧版本分别删除。中途失败或撤权时，已经删掉的版本不会自动恢复；遇到 `context_prune_partial` 时应重新盘点、重新预览，不要重放旧清单。索引重建不能恢复已删文件。

该机制沿用一个 Runner 管理同一状态目录的假设，不能协调多个独立写入进程，也不能抵御拥有主机权限的攻击者竞态修改文件。删除是普通文件移除，不是安全擦除；备份与快照也不会自动消失。

## 接入和边界

只读用户不能清理旧版本。Worker 验证参数和确认哈希，只返回允许公开的字段，并拒绝自相矛盾的“清理成功”结果。

Context 调用保留元数据审计；关闭 Job 记录不会关闭 Context 审计。存储的正文位于 Runner，盘点和清理结果不包含正文；读取 Context 时，正文可以返回给获授权的客户端。

现存 v1/v2 正文和 v1 索引保持兼容。Worker 转发 `context.storage` 或 `context.prune` 前，会检查当前 Runner 连接是否声明支持该方法。缺少支持时返回 `runner_upgrade_required` 和 `operation_state=not_started`，不会发送未知方法，也不会因此断开旧 Runner。请使用包含这些能力的已验证 Runner 发行包升级后重新连接；不能仅凭版本号判断支持情况。

## 清理范围

Prune 不删除整个上下文或最新版本，不保存自动保留策略，不提供全主机磁盘配额，不迁移未知格式，也不会清除备份。删除旧版本只能释放版本数量和字节容量。达到上下文数量上限时，此动作无法释放上下文名额；请保留数据，由管理员另行安排归档或移除。
