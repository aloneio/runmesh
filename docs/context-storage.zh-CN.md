# Context 容量与显式保留清理

这是 **R08／原计划 P13** 的开发批次，基于 `036af27aaec40f0bc879578af57e5191626a87c3`。源码验证不等于生产部署，也不覆盖不可变 v0.1.3。

## 索引上限不等于磁盘容量

原来只把索引截为 256 项，旧版本正文仍会累积，并可能把较早上下文从索引中静默挤掉。现在新增检查点达到上限时明确拒绝，不删除或隐藏已有上下文；重建也不再用截断索引假装完整。

每个工作区默认上限为：版本文件的逻辑字节 **32 MiB**、版本文件 **4,096 个**、上下文目录 **256 个**。索引另有 2 MiB 上限，意图文件和临时索引有额外有界开销。这里不是文件系统实际分配块、剩余磁盘保证，也不是整台主机所有工作区的总配额。嵌入式使用可以降低这些限制，不能无限提高或关闭；没有新增部署必填变量。

真正新增版本前才进行有界元数据盘点；完全重复的有效请求先返回原回执，因此满额不会让正常去重重试失败。旧的超额数据不自动清理或改写。未知文件、链接和不安全目录会阻止新写入或清理，不能当成可随手删除的垃圾。

## 只读查看用量

调用现有 `context` 工具，使用 `action=storage` 和 `workspace_id`。需要当前读取 scope 与工作区读取权限。返回文件数、逻辑字节、上下文数、元数据字节、限制及是否有未完成检查点；不返回绝对路径、正文或环境变量。

盘点仅扫描两层元数据，上限为 16,384 个目录项、8,192 个版本文件、1,024 个目录和检查式四秒预算。较高的盘点边界用于诊断部分历史超额状态；超限明确报错，不把部分统计冒充完整。`bootstrap/read/search` 保留定向读取；读取和预览不会建目录或重写索引。文件系统正常更新访问时间不属于接口的持久化写入。

## 清理先预览，再显式执行

示例先只生成预览：

```json
{"action":"prune","workspace_id":"workspace","keep_days":30,"keep_revisions":2}
```

预览与执行都要求 `coding:write` 和工作区编辑权限。一个旧版本必须同时满足“记录中的更新时间早于保留天数”和“不在最近指定数量的现存版本中”才可被选中。**每个上下文最新版本始终保留。**这些参数只针对当前调用，不会保存成自动清理策略。

预览返回清单哈希、候选数量／字节、仍保留的上下文数和扫描量。它会检查记录指纹、文件名、索引与最新版本关系；损坏或存在未恢复检查点时拒绝清理。预览没有正文，也不会自动执行。

审阅后，用相同参数加 `apply=true` 和返回的 `expected_plan_hash` 才执行。每批最多 128 个旧版本，可用 `max_delete` 降低。存在更多候选时返回 `has_more`，下一批仍必须重新预览和明确执行，不自动循环。

清单绑定工作区、策略代次、参数、库存文件身份和候选正文哈希。文件、新检查点或策略发生变化后拒绝旧清单。每次删除前重验候选文件、受保护的最新版本、目录链及当前授权。哈希不是授权，也不能把操作系统文件访问变成原子事务。

## 中断不假报回滚

清理不改最新记录和索引，每个旧版本分别删除。中途失败或撤权时，已经删掉的版本不会自动恢复；`context_prune_partial` 明确要求重新盘点、重新预览，不盲目重放旧清单。真实子进程在第一次删除后退出的回归会验证最新版本和索引不变，重建也不会复活已删文件。

该机制沿用一个 Runner 管理同一状态目录的假设，不能协调多个独立写入进程，也不能抵御拥有主机权限的攻击者竞态修改文件。删除是普通文件移除，不是安全擦除；备份与快照也不会自动消失。

## 接入和边界

只增加现有工具下的 `storage/prune` 子动作；公开工具仍为 10 个，受保护 RPC 增为 27 个，Runner 子动作映射为 26 个。只读用户不能通过构造请求清理。Worker 验证输入边界和确认哈希，白名单输出并拒绝自相矛盾的“清理成功”结果。

没有新增云服务、心跳、后台轮询、定时器或持久化游标。Context 调用沿用原本的元数据审计；关闭 Job 记录不等于所有 Context 调用都免审计。正文仍留本地。

现存 v1/v2 正文和 v1 索引格式保持不变。旧 Runner 不支持新方法时明确拒绝，不伪造空用量。正式安装包需要后续独立签名发版，不能把开发分支合入视为线上生效。

本批尚不删除整个上下文或最新版本，不保存自动保留策略，不提供全主机磁盘配额，也不迁移未知状态。达到上下文数量上限时，需要另行审阅完整上下文归档／删除流程；删除旧版本只能释放版本数量和字节容量。R08 的其余治理和状态版本演进仍单独保留。
