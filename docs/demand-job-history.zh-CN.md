# 按变化记录 Job 历史

按变化记录会在可记录的 Job 状态变化时上传近期元数据，确认收到后停止历史计时器。此功能属于 **0.1.4 候选版**，需要兼容的 Worker／Runner 及 D1 历史配置。

## 启用与设置

在 **管理界面 > MCP 客户端 > 客户端详情 > 云端任务记录** 中选择记录偏好，在 Runner 的 **任务记录与保留** 中设置上传模式和间隔。控制面在授权启动时提供记录决定。

Runner 声明 `capabilities.labels.job_reporting_protocol="2"`，并在认证 welcome 中收到 `runmesh_job_reporting:2` 后，启用记录协议 2。它沿用 `job_history_protocol="1"` 的设置，详见[任务记录设置](batched-job-history.md)。

创建时关闭记录的 Job 会从上传候选和心跳活动任务 ID 列表中排除。执行、本地元数据、日志和控制操作仍可通过带工作区的实时请求访问。`job.logs` 只读取请求的本地日志页；记录偏好通过管理员设置修改。

相同有效启动标识的重试返回原 Job 及其记录决定。排队任务启动前重新授权，可以进一步限制记录。重新开启偏好后，原来未记录的 Job 仍保持未记录状态。

偏好变化在云端归档准入和新任务启动时生效。此前允许记录的 Job 仍可能发送元数据，随后由云端过滤；已经准入的上传也可能完成。已有云端历史继续遵循保留设置，重新开启则开始新的记录窗口。

## 上传行为

| 情况 | 协商成功后的行为 |
| --- | --- |
| Runner 全局历史关闭 | 停用历史采样和上传调度 |
| 历史开启后认证连接成功 | 对允许保留的元数据进行一次有界恢复采样；空采样在本地完成 |
| 可记录 Job 状态变化 | 合并待确认变化；批量模式等待配置间隔，即时模式安排下一轮发送 |
| 只有不记录任务执行，或读取日志 | 这些活动保持历史调度空闲 |
| 状态已确认且没有更新变化 | 停止历史计时器 |
| 收到 `recorded` 或 `unchanged` | 确认该次采样代次，之后的新变化继续等待上传 |
| 延后、退化、丢回执或采样／发送失败 | 保留待确认变化，从配置间隔开始指数退避，最长一小时 |
| 重试期间没有新变化 | 重用已捕获的有界结果 |
| 收到 `disabled` | 停止该连接的历史调度，等待新认证连接提供设置 |
| 断开或停止 | 取消连接的计时器和采样状态；重连后重新认证、采样 |

可记录的恢复进程处于 `unknown` 时，在结果未明确期间保留有界检查机会，因为重启后的 Runner 没有这些进程的退出回调。策略变化也可能触发采样。未记录的恢复任务由显式实时查询和执行准入触发状态检查。

## 容量与开销

每次采样最多 **500 条元数据**，并受消息大小及本地保留限制；每个连接保留一份采样结果。它用于近期快照，本地和云端保留规则都可能移除记录。需要完整长期执行历史时，应另外保存。命令正文、stdout／stderr、主机路径及排队凭据不进入云端任务历史。

空更新也会检查传输身份和当前记录偏好。过滤后没有 Job 时，Registry 在访问 D1 前返回 `unchanged`。已有云端历史由保留机制清理。授权、心跳、普通归档和清理仍有正常资源开销。

## 兼容性

| 组合或状态 | 行为 |
| --- | --- |
| 兼容 Worker 和 Runner，D1／协议 2 协商成功 | 源头过滤及按变化记录 |
| 兼容 Worker 配旧 Runner | 保留原 Runner 调度和云端过滤；空候选更新跳过 D1 |
| 新 Runner 配旧 Worker | 协商前使用兼容调度；明确标记不记录的本地任务继续排除 |
| SQLite 后端 | 使用已有兼容历史行为 |
| 没有记录标记的旧任务 | 符合条件的有界元数据可以上传，并接受当前云端过滤 |
| 回退旧程序 | 旧代码可能忽略或移除记录标记；依赖源头过滤前，应用备份验证回退行为 |

先部署兼容 Worker，再安装包含功能的已验证 Runner 发行包，最后检查实际协商结果。Worker 部署和 Runner 安装是两个升级步骤。
