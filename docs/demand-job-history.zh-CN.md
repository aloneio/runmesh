# 按变化调度 Job 历史

实施基线：`ab3ad6d66fc54792e3a4c77e4e1a298d16612358`。本文描述开发源码，不表示生产 Worker 或已安装的不可变 v0.1.3 已升级。

## 执行、日志读取和云端历史分别处理

`job.logs` 只读取本次请求的本地日志页，不开启记录、不创建订阅。前台执行结果不等待历史归档间隔。本地 Job 元数据、stdout/stderr、回执、取消和恢复不依赖可选的云端记录。

新 Runner 声明 `capabilities.labels.job_reporting_protocol="2"`，并收到认证 welcome 中的 `runmesh_job_reporting:2` 后，现有 D1 历史路径启用源头过滤和按变化调度。原 `job_history_protocol="1"` 设置格式不变，不增加部署变量，也不向普通 MCP 调用方开放可伪造的记录参数。

## 可信的创建时记录决定

最终 Registry 授权复用已经读取的客户端记录，可附带内部 `record_history` 决定，不增加一次远程查询。RunnerDO 删除调用参数中自带的记录标记和排队凭据，只给协商成功的 Runner 注入可信决定，并将其绑定到既有排队启动摘要。实际执行授权、会话和策略检查不变，最终本地检查到发送之间不增加异步等待。

Runner 创建新 Job 时将这个可选布尔值保存在本地。明确为 false 的任务在排序和数量截断之前就排除出上传候选，不因状态变化启动历史计时器，其 ID 也不放进独立心跳的活动任务列表。心跳频率和在线判定不变。此标记不进入云端 Job 元数据或公开工具结果。

相同请求重试返回原 Job，不能把原本不记录的任务改为记录。出队时的最新授权可进一步关闭记录，不能开启原本为 false 的任务。已存标记格式非法时按 false 处理，但不丢弃其他部分仍可恢复的进程记录。旧记录不会为了升级而被批量改写。

云端仍检查当前偏好与记录起始窗口。创建之后修改偏好不会同步广播到所有运行任务：此前允许记录的任务仍可能上传，再由云端过滤；已准入的归档也可能完成。重新开启不会补录创建时明确不记录的任务，关闭不会删除既有云端历史。

## 调度规则

| 情况 | 协商成功后的行为 |
| --- | --- |
| Runner 全局历史关闭 | 不创建历史启动采样、上传计时器或历史快照 |
| 历史开启后认证连接成功 | 一次有界启动／恢复采样；没有候选时不发送归档消息 |
| 可记录任务状态变化 | 标记有未确认变化，合并为一个上传机会；批量模式等待配置间隔，即时模式安排下一轮发送 |
| 只有不记录任务执行，或读取日志 | 不因此创建历史计时器 |
| 已确认且没有更新变化 | 不保留周期历史扫描或上传计时器 |
| 收到 recorded／unchanged 回执 | 只确认该批次的变化代次，不覆盖并发新增变化 |
| 延后、退化、丢回执或采样／发送失败 | 保留待确认变化，单次计时重试按配置间隔指数退避，上限一小时 |
| 重试期间没有新变化 | 重用有界快照，不反复遍历本地任务 |
| 收到 disabled | 停止该连接的历史调度，新的认证连接设置才能恢复 |
| 断开或停止 | 取消旧计时器及连接级缓存；新连接重新认证后进行启动采样 |

重启后仍为 `unknown` 的可记录进程没有本次 Runner 的退出事件，因此未解决期间保留有界恢复检查；普通子进程在状态已确认后不需要持续检查。策略变化也可请求一次有界采样。这些例外不是长期空闲扫描，更不是日志订阅。不记录的恢复任务仍可由既有执行准入和显式查询触发恢复检查。

每次最多 500 条元数据，继续遵守线协议、内存和本地保留上限；每个连接只缓存一份待确认快照。这是近期快照，不是无损事件档案或“精确一次”保证。不增加命令、日志正文、主机路径或排队凭据的云端记录。

## 云端空批次也不访问 D1

Registry 保留会话身份和当前记录偏好检查。过滤后为空时，直接返回 unchanged，不打开 D1。空批次不表示删除既有历史，保留清理由独立路径负责。已有授权读取、心跳、正常归档和维护仍有成本，不能称为整个账户零消耗。

## 兼容与上线边界

新 Worker、新 Runner、D1 设置及记录协议 2 全部协商成功，才同时具备源头过滤和按变化调度。新 Worker 配旧 Runner 仍使用原有上传协议，但空候选不会再访问 D1。旧 Worker 配新 Runner 保留旧调度；SQLite 兼容路径也不冒充已启用新 D1 协议。

没有新标记的旧本地记录保留 legacy／unknown 语义，不能猜测历史上是否允许记录；这些有限元数据仍可能上传，由云端当前窗口过滤。回退旧程序可能忽略或丢弃新字段，必须保留状态备份，不可在未经验证的降级后继续承诺源头不报。

生产应在另行授权后部署兼容 Worker，再通过新的已验证签名包受控升级 Runner。本批开发提交不覆盖官方 v0.1.3、不重新注册、不更改记录开关，也不重启唯一维护连接。

## 验证范围

回归覆盖源头过滤与数量上限、实际本地执行／读日志、重启保留、重复请求不补录、双客户端、排队时限制、签名绑定、最终授权拒绝／策略竞态、能力协商、空批次零 D1、代次确认、重试退避、缓存重试、重连取消和恢复进程例外。

真实回环测试使用 Runner、子进程和 WebSocket，仅替换上传时钟。288 次模拟机会不是生产跑满一天的指标。源码及独立安装包端到端另测管理员偏好经实际 MCP／Worker／Runner 链路生效。测试不接触生产数据、服务状态和正式资产。
