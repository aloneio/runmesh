# MCP 公开输出契约（AR05）

保持既有十个公开工具名称及输入 Schema。每个工具都有明确的封闭输出 Schema，不再用任意字段透传对象兜底。现有白名单投影继续负责秘密／路径过滤和响应预算。

`mcp/output-contracts.ts` 描述公开元数据和聚合工具输出；旧端缺少的观测字段保持可选，不伪造数值。`mcp/action-output-contracts.ts` 为现有 `MCP_RPC_ACTIONS` 中的每个动作定义必需证据和封闭结构，以 TypeScript 和回归测试核对完整性。`tools/list` 发布稳定的聚合 Schema，工具返回成功前再根据输入动作校验。

`mcp/handler-registry.ts` 要求每个公开工具恰有一个自有普通属性回调。缺少、多余、继承或 getter 回调会在注册前失败。现有服务仍按请求重新验证凭据与 scope，注册表不缓存或授予权限。

无效的成功输出返回 `tool_result_invalid`，操作状态保持未知。可以保留安全的既有 Job／工作区／调用标识及审计观察，但不暴露私密字段或校验异常详情。命令、输入、补丁和取消不会自动重放。原有错误结果走原路径；命令已结束而日志不可用时仍保留真实状态和退出码。

## 兼容性与限制

明确的有界截断结果继续支持，空对象不能当作成功回执。旧端可以缺少可选观测，但错误类型、未声明字段和缺失动作必需证据会被拒绝。例如 `job.input` 返回接收字节数 `accepted` 和可选 `eof`，不是 JobRecord；原过宽测试模拟已修正，并增加反向回归。

聚合 JSON Schema 不能表达它对另一份请求中 action 的依赖，这由动作校验完成。本阶段不等于完整 Worker／Runner 强类型 RPC 重构、能力禁用开关或宿主缓存自动刷新。公开目录指纹会随输出 Schema 改变。不新增公开工具、必填运行变量、RPC、持久化记录或定时器，但 Schema 校验和更大的目录有 CPU／传输开销，不能称为零成本。

验证覆盖固定合法／非法输出、handler／action 完整性、真实 MCP 传输、不记录模式及权限回归、安装包端到端。源码、测试、正式资产和生产激活分别验收。
