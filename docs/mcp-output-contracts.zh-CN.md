# 读取与校验 MCP 工具结果

当前 Worker 在 `tools/list` 中为十个公开 MCP 工具分别公布输出 Schema。请按对应 Schema 解释成功结果。旧 Runner 无法提供的可选观测字段可能缺失；缺失不代表数值为零，也不能证明操作已经完成。

Worker 返回成功前，会按请求动作检查结果，只返回允许公开的字段，不转发私密元数据或原始异常详情。响应仍有大小上限，因此成功结果也可能明确标记已截断。

## 结果无法确认时

无效的成功输出返回 `tool_result_invalid`，操作状态保持未知。可以保留安全的既有 Job／工作区／调用标识及审计观察，但不暴露私密字段或校验异常详情。命令、输入、补丁和取消不会自动重放。原有错误结果走原路径；命令已结束而日志不可用时仍保留真实状态和退出码。

## 兼容性与限制

明确的有界截断结果继续支持，空对象不能当作成功回执。旧端可以缺少可选观测，但错误类型、未声明字段和缺失动作必需证据会被拒绝。例如 `job.input` 返回已接受的字节数 `accepted` 和可选 `eof`，不是 JobRecord，也不证明子进程已处理这些输入。

聚合 JSON Schema 无法表达对请求动作的全部依赖，Worker 会额外检查这些关系。合法 Schema 不授予权限，也不证明每个 Runner 都支持对应操作。公开目录指纹会随 Schema 改变，但客户端可能保留旧缓存；目录过期时请刷新对应连接器。详见[能力诊断](capability-contracts.zh-CN.md)和[调用恢复](mcp-agent-call-contract.md)。
