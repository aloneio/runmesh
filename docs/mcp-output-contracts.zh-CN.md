# 读取与校验 MCP 工具结果

按 `tools/list` 中的输出 Schema 解释 Runmesh 的十个公开工具。Worker 会根据请求动作校验成功结果，在响应大小预算内返回允许公开的字段。结果被截断时会明确标记。

## 解释回执

旧 Runner 可能省略可选观测字段。将这些字段视为暂不可用，并依据实际返回的证据判断。例如，`job.input` 的 `accepted` 表示已接受的字节数，可选 `eof` 表示输入结束；进程如何处理输入，需要继续查看 Job 的输出和状态。

每个动作必须提供相应的结果证据。字段类型错误、未声明字段、缺少必需证据或空成功对象会触发 `tool_result_invalid`。这些动作检查与公开的聚合 JSON Schema 共同约束结果。

## 处理无效结果

`tool_result_invalid` 的操作状态为未知。保留已有的 Job、工作区和调用标识，先检查原操作，再决定下一步。**结果未知时，不要自动重放命令、输入、补丁或取消请求。**错误详情只包含可安全公开的元数据。

命令已结束而内嵌日志读取失败时，使用实际状态和退出码，只重试日志查询。详见[调用恢复](mcp-agent-call-contract.md)。

## 刷新过期目录

工具目录指纹随 Schema 变化。请对照 MCP 客户端实际加载的目录与已部署 Worker 的目录，必要时刷新对应连接器。[能力诊断](capability-contracts.zh-CN.md)还会分别报告 Runner 支持情况和当前权限；每次操作都需要同时满足这两个条件。
