# Registry 内部分域

修改 Registry 逻辑时，可按本文确认模块职责。各领域模块共享同一个 Registry Durable Object 和同步存储所有者，不是独立数据库或网络服务。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `registry.ts` | 保留公共兼容入口、DO 初始化和 Schema、HTTP 路由、现有维护与外部历史协调 |
| `registry/auth.ts` | 管理员会话、密码代次、限流退化、MCP 凭据与固定 Runner 选择 |
| `registry/policy.ts` | 当前授权、权限交集、工作区变更、策略版本和确认 |
| `registry/lifecycle.ts` | Runner 注册与兑换、凭据变更回执、连接代次、心跳、撤销和身份绑定读取 |
| `registry/history.ts` | 本地元数据快照、单调 Job 更新、入库时的记录偏好、读取投影和审计保留 |
| `registry/ports.ts` | 每个领域实际需要的窄协作接口，不依赖具体 DO 或其他服务类 |
| `registry/storage.ts` | 同一个原生 SQL 句柄和同步事务所有者，不增加缓存、重试、批处理或 Promise |
| `registry/records.ts`、`registry/values.ts` | 内部数据类型、固定默认值及原有字段验证与投影 |

组装入口只注入各领域实际需要的类型化函数，不把整个 Registry、Worker 环境、DO 上下文或另一个服务对象传进去。四个服务构造时均不访问 SQL、网络或凭据存储，不创建表、设置 alarm 或发现环境。

原有公共方法签名和导出保持兼容。服务内部为跨领域协作开放的方法，不等于新增公开 HTTP 路由或 MCP 工具。

## 不能移动的事务和授权边界

仍然只有一个 Registry DO 和一个数据库事务所有者。同步 SQL 适配器直接转交原来的 `transactionSync`，保留返回值和异常；协作接口不引入 `await`。注册 Runner 时创建策略快照仍处于同一事务中，策略写入失败会一起回滚 Runner、凭据变更回执和策略记录。

协作接口执行当前操作，不代表可缓存的授权快照。修改时应保留同步授权边界，并区分数据库不可用、实际拒绝、过期策略、非法记录和可选历史退化。领域服务构造函数不修复或迁移持久化记录。

SQL 按业务职责归组，并没有被包装成通用异步仓储。删除 Runner、替换凭据、修改记录偏好等原有原子操作会跨表；这些跨表事务有意保留，不能宣称每个领域已经独占一组互不交叉的表。

HTTP／HMAC 路由顺序、DO 初始化、维护调度、功能健康协调和 D1 边界处理由入口负责。调整模块边界时，跨领域事务仍应保留在同一存储所有者中。

## 验证

在未修改的基线代码上记录 40 个操作场景，逐项保存 SQL 及参数顺序摘要、事务开始／提交顺序、实际读取／写入行数和返回结果。场景包括会话与密码更换、nonce 重放、注册与重试、权限与策略确认、最终授权、心跳重放、Job 快照、不记录模式、凭据轮换及撤销后的旧会话。所有输入都是合成测试数据。

另有跨领域写失败回滚、无副作用构造、同步存储适配及窄 SQL 接口测试。原有注册、权限、撤销、休眠、额度、历史和真实 MCP 集成回归不减少。

最初 AR06 提取曾对照 `ca511cf0fa9411b85a52ba78547aeab7e4b27dec` 检查结构兼容性。该历史对照不能验证后续源码修改；每次改动仍需运行相关回归。

架构门禁新增约束：领域模块不能导入 Registry 入口、具体同级服务、MCP／UI 或远程历史适配器；基础类型与端口不能反向依赖领域实现。继续由两端已有 CI 执行。

## 兼容性与资源消耗

验证兼容性时，除 JSON 结果外，还应检查 SQL 顺序和实际行数。正常 SQL 与认证会消耗资源；本地测试不能证明账户总费用或生产容量。

部署或回退前，应核对目标完整版本的存储兼容性。按[升级指南](upgrading.zh-CN.md)保留现有资源；模块重组本身不构成重置存储的理由。
