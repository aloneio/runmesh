# Registry 内部分域

修改 Registry 逻辑时，可按本文确认模块职责。所有领域模块运行在同一个 Registry Durable Object 中，共享其同步存储所有者。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `registry.ts` | 保留公共兼容入口、DO 初始化和 Schema、HTTP 路由、现有维护与外部历史协调 |
| `registry/auth.ts` | 管理员会话、密码代次、限流退化、MCP 凭据与固定 Runner 选择 |
| `registry/policy.ts` | 当前授权、权限交集、工作区变更、策略版本和确认 |
| `registry/lifecycle.ts` | Runner 注册与兑换、凭据变更回执、连接代次、心跳、撤销和身份绑定读取 |
| `registry/history.ts` | 本地元数据快照、单调 Job 更新、入库时的记录偏好、读取投影和审计保留 |
| `registry/ports.ts` | 各领域通过类型化窄接口协作 |
| `registry/storage.ts` | 直接访问同一个原生 SQL 句柄和同步事务所有者 |
| `registry/records.ts`、`registry/values.ts` | 内部数据类型、固定默认值及原有字段验证与投影 |

组装入口完成初始化，并为各领域注入所需的类型化函数。构造函数只保存这些依赖；生命周期服务接收所需的凭据 pepper，策略服务接收历史后端选择值。完整 Worker 环境与 DO 上下文由入口管理。

入口管理公共方法、路由和兼容导出。领域服务通过类型化端口调用内部协作方法。

## 事务和授权顺序

Registry DO 统一管理数据库事务。同步 SQL 适配器直接转交 `transactionSync`，保留返回值和异常；协作接口同步执行。注册 Runner 与创建策略快照处于同一事务中，策略写入失败会一起回滚 Runner、凭据变更回执和策略记录。

协作接口按当前授权执行操作。修改时保留同步边界，并区分数据库不可用、实际拒绝、过期策略、非法记录和可选历史退化。持久化初始化与受支持的迁移在 DO 启动阶段完成。

SQL 按业务职责归组。删除 Runner、替换凭据和修改记录偏好等原子操作涉及多个领域使用的表。调整模块时，继续在同一个同步事务中完成这些跨表操作。

HTTP／HMAC 路由顺序、DO 初始化、维护调度、功能健康协调和 D1 边界处理由入口负责。调整模块边界时，跨领域事务仍应保留在同一存储所有者中。

## 验证

在未修改的基线代码上记录 40 个操作场景，逐项保存 SQL 及参数顺序摘要、事务开始／提交顺序、实际读取／写入行数和返回结果。场景包括会话与密码更换、nonce 重放、注册与重试、权限与策略确认、最终授权、心跳重放、Job 快照、不记录模式、凭据轮换及撤销后的旧会话。所有输入都是合成测试数据。

另有跨领域写失败回滚、无副作用构造、同步存储适配及窄 SQL 接口测试。修改相关行为后，运行注册、权限、撤销、休眠、额度、历史和真实 MCP 集成回归。

最初 AR06 提取对照 `ca511cf0fa9411b85a52ba78547aeab7e4b27dec` 检查结构兼容性。后续每次修改，都应针对新的候选提交运行相关回归。

两端 CI 的架构门禁检查依赖方向：领域依赖基础类型和窄接口，入口将领域与 HTTP、外部历史适配器组装起来。领域导入 Registry 入口、具体同级服务、MCP／UI 或外部历史适配器时，检查会失败。

## 兼容性与资源消耗

验证兼容性时，同时比较 JSON 结果、SQL 顺序和实际行数。账户总费用和生产容量在目标 Cloudflare 环境中测量。

部署或回退前，核对目标完整版本的存储兼容性。模块重组期间按[升级指南](upgrading.zh-CN.md)保留现有资源。
