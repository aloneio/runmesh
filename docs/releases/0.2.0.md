# Runmesh 0.2.0

Runmesh 0.2.0 improves the shared MCP and Skill experience and makes the control panel easier to use.

## For users

- Renamed Skills keep the name you chose in the Central list after a refresh.
- Deleted Skills stay deleted. The same Skill ID cannot be reused, which prevents an old package from returning by accident.
- The Central list shows the friendly name you gave a Skill while keeping its original identity for updates.
- MCP and Skill management pages explain connection, update, pause, and removal actions in plain language.
- Runner and client lists keep their friendly names when you return to the page.

## For administrators

- The release includes the reviewed Skill rename and deletion lifecycle.
- The Runner Git check reports when Git is unavailable instead of treating an incomplete check as a clean repository.
- Remote MCP capacity is reported separately from the availability of an already configured connection.
- Existing connections, Runner registrations, workspaces, and credentials remain in place during a compatible upgrade.

Read the [upgrade guide](https://github.com/aloneio/runmesh/blob/main/docs/upgrading.md) before updating an existing installation. The [release status](https://github.com/aloneio/runmesh/blob/main/docs/release-readiness.md) page lists the signed Runner package and current installation path.

# Runmesh 0.2.0（中文）

Runmesh 0.2.0 改进了共享 MCP 与 Skill 的使用体验，也让控制台操作更清晰。

## 用户可见变化

- Skill 重命名后，中央列表会保留你设置的名称，刷新页面也不会恢复原名。
- 已删除的 Skill 会保持删除状态；原 Skill ID 不能再次复用，避免旧内容意外回来。
- 中央列表显示你设置的友好名称，同时保留 Skill 原有身份用于后续更新。
- MCP 和 Skill 管理页面用更直白的文字说明连接、更新、暂停和删除操作。
- 返回页面后，Runner 和客户端列表会继续显示已设置的友好名称。

## 管理员可见变化

- 本版本包含 Skill 重命名与删除生命周期的正式实现。
- 当 Runner 无法使用 Git 时，检查会明确报告“Git 不可用”，不会把不完整的检查当成干净仓库。
- 远端 MCP 目录容量不足与已经配置的连接是否可用分开报告。
- 兼容升级会保留现有连接、Runner、工作区和凭据。

更新已有实例前，请阅读[升级指南](https://github.com/aloneio/runmesh/blob/main/docs/upgrading.zh-CN.md)。[发行状态](https://github.com/aloneio/runmesh/blob/main/docs/release-readiness.zh-CN.md)会列出签名 Runner 安装包和当前安装方式。
