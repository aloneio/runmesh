# 更换 Runner 版本

[English](runner-versions.md) · [文档目录](README.zh-CN.md)

在控制台打开 **Runner**，选择计算机，通过 **Runner 版本**安装当前环境的最新版或指定发行版。切换到旧版本也使用同一个表单。

## 选择版本

1. 打开 Runner 详情页。
2. 选择最新版，或选择指定版本并填写完整版本号，例如 `0.1.7`、`0.1.7-dev.123`。
3. 应用更改。页面会显示目标版本和处理进度。

最新版跟随控制端所属环境：dev 实例使用开发版 Runner，正式实例使用正式版 Runner。填写完整版本号可以直接选择对应发行版，也可以选择更早的版本。各版本提供的功能见[版本说明](release-notes.zh-CN.md)。

## 切换过程

Runmesh 会验证发行包，暂停向这台 Runner 发送新请求，并等待本机任务结束。随后切换程序包，确认目标版本重新连接控制端。Runner 的身份、工作区、凭据、任务记录和服务账号会继续保留。

如果目标版本启动或重连失败，版本管理器会恢复原来的程序包，页面会显示处理结果。切换意外中断时，管理器会在下次启动后根据本地记录恢复。

建议先让运行中的任务完成，再切换版本。任务需要处理时，可在任务列表或计算机上完成处理，然后重新提交版本切换。计算机休眠或断网时，版本管理器会在恢复连接后接收请求。

## 为已有计算机启用远程版本管理

[当前开发版 Runner](dev-runner-prereleases.zh-CN.md)为标准受管安装提供版本管理器。它独立于选定的 Runner 程序包运行，因此切换到旧版后仍可再次远程升级。

更换 Runner 版本时，会保留这台计算机已经安装的版本管理器。

切换版本后，`restart`、`install`、`uninstall` 等服务管理命令也继续使用独立管理器。服务卸载和完整清理步骤见 [Runner 卸载指南](runner-uninstall.md)。

旧安装首次启用时，先部署上述已经验签的开发包，保留原配置和服务布局。用更新后的服务程序运行 `--help`，确认包含 `maintenance-agent`，再使用原配置执行 `install`。系统服务使用管理员会话；用户级服务使用所属账号，并添加 `--user`。确认安装结果显示 `remote_version_management: available`。

标准受管安装使用 `current` 链接和 `versions` 目录。自定义部署路径的服务，按原来的程序包部署流程更新。
