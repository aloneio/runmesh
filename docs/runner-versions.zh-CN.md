# 更换 Runner 版本

[English](runner-versions.md) · [文档目录](README.zh-CN.md)

在控制台打开 **Runner**，选择计算机，通过 **Runner 版本**安装当前环境的最新版或指定发行版。切换到旧版本也使用同一个表单。

远程版本管理需要 0.1.8 或后续兼容版本的控制端，并先从对应 Runner 包安装独立管理器。当前正式包见[发行状态](release-readiness.zh-CN.md)，预览版本见[开发渠道](dev-runner-prereleases.zh-CN.md)。

## 选择版本

1. 打开 Runner 详情页。
2. 选择最新版，或选择指定版本并填写完整版本号，使用[发行状态](release-readiness.zh-CN.md)或开发渠道页面显示的完整版本号。
3. 应用更改。页面会显示目标版本和处理进度。

最新版跟随控制端所属环境：dev 实例使用开发版 Runner，正式实例使用正式版 Runner。填写完整版本号可以直接选择对应发行版，也可以选择更早的版本。各版本提供的功能见[版本说明](release-notes.zh-CN.md)。

## 切换过程

Runmesh 会验证发行包，暂停向这台 Runner 发送新请求，并等待本机任务结束。随后切换程序包，确认目标版本重新连接控制端。Runner 的身份、工作区、凭据、任务记录和服务账号会继续保留。

如果目标版本启动或重连失败，版本管理器会尝试恢复原来的程序包，页面会显示处理结果。切换意外中断时，管理器会在下次启动后根据本地记录继续恢复。页面报告 `rollback_failed` 或 `local_state_invalid` 时，先检查主机服务与保留的更新状态，再申请另一次切换。回滚失败时，维护隔离会持续保留，直至恢复完成。

未完成的版本切换应使用原 Runner 注册身份和控制端地址完成恢复。如果重新注册或更换服务器中断了恢复，保留本地更新记录，恢复原 profile 后重试。

建议先让运行中的任务完成，再切换版本。管理器等待本机工作结束的单次窗口为 15 分钟；页面报告 `busy_local_jobs` 时，可在任务列表或计算机上完成处理，然后重新提交版本切换。计算机休眠或断网时，版本管理器会在恢复连接后接收请求；空闲时通常每 30–60 秒检查一次请求。

## 为已有计算机启用远程版本管理

包含版本管理器的签名 Runner 包为标准受管安装提供远程更新功能；包的选择与首次启用步骤见[升级指南](upgrading.zh-CN.md)。它独立于选定的 Runner 程序包运行，因此切换到旧版后仍可再次远程升级。

更换 Runner 版本时，会保留这台计算机已经安装的版本管理器。

更新管理器时，使用 0.1.9 引入的独立 [`manager-refresh` 流程](upgrading.zh-CN.md#更新已安装的版本管理器)。从已验签发行包的独立目录执行维护程序，保留管理器身份与状态、已有 Node 运行时、Runner 配置、工作区及服务启用状态。要使用 0.1.9 的 Windows 版本切换改进，已有安装先更新管理器，再在控制端选择目标 Runner 版本。首次安装使用所选包自带的管理器。

更新前先完成当前版本变更及恢复处理。命令提示维护忙碌时，让当前操作完成后重试；中断后保留同一份已验签包并重复原命令，继续恢复。[升级指南](upgrading.zh-CN.md#更新已安装的版本管理器)提供各平台路径和完整命令。

切换版本后，`restart`、`install`、`uninstall` 等服务管理命令也继续使用独立管理器。服务卸载和完整清理步骤见 [Runner 卸载指南](runner-uninstall.md)。

尚无管理器的标准系统服务，按[标准受管 Runner 升级流程](upgrading.zh-CN.md#更新尚未启用版本管理器的标准受管-runner)执行共用命令，并完成[管理器首次启用](upgrading.zh-CN.md#切换程序后首次启用管理器)。流程适用于 `0.1.6-dev.26` 等旧开发包，验证精确签名目标及独立维护包，保留原配置、状态、Runner 身份和服务参数，无需重新注册或完整卸载。已安装的管理器在 Runner 回退到旧版后仍然保留，选择首次启用流程前先核对主机。

首次启用使用原 profile 和执行模式运行 `install`；已有 `privileged_host` 系统服务仍须添加 `--confirm-privileged-host`。确认结果为 `remote_version_management: available`，本机管理器服务正在运行，控制台请求继续推进。启动前先核对排队目标，管理器会先处理该请求。待其完成或按升级指南恢复后，再提交另一个目标版本。

标准受管安装使用 `current` 链接和 `versions` 目录。用户级服务按[对应流程](upgrading.zh-CN.md#更新用户级服务)使用所属账号和 `--user`；自定义部署路径按原来的程序包部署方式更新。出现 `manual` / `custom_service_layout` 时，检查实际服务定义。

## 请求一直等待或安装器提示版本不同

如果页面一直显示“等待主机管理器领取”，先在主机上检查版本管理器服务。早于管理器功能的 Runner 先完成上面的首次启用步骤，再跟进原版本请求。

安装器提示 `installed Runner version differs from the fixed release` 时，已有安装仍在。托管安装命令用于首次安装或同版本重新注册；尚无管理器的标准受管安装按[参数化包迁移流程](upgrading.zh-CN.md#更新尚未启用版本管理器的标准受管-runner)暂存验签包并切换程序，保留现有身份、配置与任务记录。

完整卸载会移除安装并清除本地任务记录，项目工作区继续保留。使用当前签名维护包执行清理；遇到目录重叠提示时，按 [Runner 卸载指南](runner-uninstall.md)核对工作区和安装路径，再继续操作。
