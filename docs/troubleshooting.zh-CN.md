# 故障排查

[English](troubleshooting.md) · [文档目录](README.zh-CN.md)

先定位出错组件：管理后台、Worker、Runner 服务或 MCP 客户端。保留原操作回执。问题报告不要包含密码、MCP 地址、注册命令、token 或私有输出。

## 管理页面或登录不可用

检查部署的公网 HTTPS 地址与状态。普通直接生产部署不要求手工设置 `RUNMESH_PUBLIC_ORIGIN`；只有明确配置了覆盖值，例如反向代理场景，才需要核对它。未初始化实例应先完成设置，再向不可信访问者开放。

Registry 故障或依赖响应无效时，应检查部署并等待服务恢复，不能直接断定密码错误或轮换密钥。确实因多次错误登录被节流时，等待节流窗口结束。修改密码会使旧会话失效，按需重新登录。

数据结构不匹配应检查所部署代码和绑定，不能把新建命名空间、删除 D1 或重新初始化当作已有 v2 实例的通用修复。先保护数据，参阅[升级指南](upgrading.zh-CN.md)；[旧版本迁移](migration.md)属于适用范围明确的另一项操作。

## Runner 一直离线

检查真实主机服务、到 Worker 的 HTTPS/WebSocket 出站连接和系统时间。使用服务实际调用的程序运行 `runmesh --version` 与 `runmesh doctor --json`。另一份本地 CLI 或正常的 Worker 健康页面，都不能证明该服务已连通。

检查 Runner 授权、策略确认和明确的凭据拒绝原因。Runner 授权期限到期可由管理员延长，不能把网络故障当作凭据丢失。只有确认凭据已撤销、替换或配置不兼容时，才使用管理员审核的恢复注册流程。不要仅因调用超时就重新注册健康 Runner。

Runmesh 连接不需要公网入站端口，不要为了恢复该连接而开放 Runner 或额外开放 SSH。

## 安装失败或显示不可用

使用对应系统的管理员终端，完整复制注册页面命令。`RMI_*` 错误参阅[安装依赖](installer-prerequisites.zh-CN.md)。注册码可能已被消耗时，不要盲目重试。

安装器不可用可能是签名发行物或部署检查尚不满足要求。只有存在适用且可验证的包时，才按[便携包校验流程](portable-runner-installation.md)操作；不要改用软件包注册表中的包名、源码分支构建或未验证镜像。不能关闭 TLS、签名或哈希校验。已有安装或服务清单冲突应由管理员检查，不要强制覆盖或清空状态。

## MCP 无法连接或工具参数不一致

使用以 `/mcp` 结尾的完整地址，不附加引号、空格或 Bearer token。确认客户端支持 Streamable HTTP，且地址仍被授权。

Worker 更新后刷新 Runmesh 连接与缓存的工具定义。缺少动作或任务后续查询拒绝 `workspace_id`，可能是工具目录或组件版本不匹配。核对已部署 Worker、已安装 Runner 和鉴权后返回的工具目录。当前源码示例不能让旧组件获得尚未实现的能力。详见[目录刷新说明](mcp-connector-refresh.md)。

## 没有工作区或权限不足

客户端、Runner 和工作区必须同时允许操作。检查客户端 scope、Runner 限制、授权期限和已确认的工作区策略，再用 `runner_current`、`workspace_list` 确认。不能靠扩大权限处理依赖故障，也不要通过绝对路径、符号链接或命令绕过拒绝。

## Shell 已返回，但任务仍运行或云端查不到

前台等待时间不是命令执行期限。保留 `job_id` 和 `workspace_id`，保持原 Runner 选择，查询原任务。`job_history_unavailable` 或旧版本的 `not_found` 不能证明命令没有执行。使用组件支持的带工作区在线查询；后续查询链路异常时请管理员排查，不要重新启动命令。

云端历史可能被关闭、延迟、过期或暂不可用。本地实时输出需要 Runner 在线且授权有效。已归档元数据只是近期快照，不是实时进程状态的权威结果，也不是完整日志归档。

## 取消、恢复或输入结果不确定

`queued`、`running`、`cancelling`、`unknown` 都不是成功结束。发出取消请求不代表进程立即退出。重启后无法确认身份的进程可能继续占用执行槽，直到状态核对完成；不要删除元数据或猜测 PID 来释放槽位，应由管理员检查主机。

输入送达失败或超时，不表示进程一个字节也没有收到。重新发送数据或输入结束信号前，先检查原进程。有 `operation_state`、`next_action` 和 `recovery_hint` 时应结合这些字段判断，不能只看错误码。完整任务状态说明见[用户指南](user-guide.zh-CN.md)。

## 输出不完整

前台输出的正数偏移可能只是响应只返回了末尾片段，可对原任务分页读取保留日志。`output_truncated` 也可能表示存储上限已经丢弃部分字节；Runmesh 无法恢复被丢弃的内容，只能在另有配置时检查应用自身日志。读取日志不会开启云端记录。

## 报告仍未解决的问题

提供时间、工具及动作、版本、脱敏错误代码和非敏感诊断结果，不附带凭据、完整地址、真实工作区路径或私有内容。安全问题按 [SECURITY.zh-CN.md](../.github/SECURITY.zh-CN.md) 私密反馈。
