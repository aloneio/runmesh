# 界面本地化约束

管理界面支持英文与简体中文。显式 `lang` 查询参数优先于 `runmesh_lang`
Cookie，再按 `Accept-Language` 权重选择。地区或文字变体回退到已支持的
英文或简体中文词库。合法的显式选择通过 HTML 响应保存，并保留现有会话 Cookie。

## 区分界面文案与原始数据

模板使用编写好的消息与英文兼容词条；新增消息使用 `i18n/messages.ts` 中的类型化键。由服务端在首屏前翻译完整文案节点和指定的无障碍
属性。动态说明按明确的标记边界分段，用户数据与翻译键分开处理。
服务端输出所选语言，浏览器直接呈现结果。

`ui-catalog.ts` 使用单一只读映射，测试拒绝重复键与追加覆盖。同词不同义应
使用不同原文：工作区的 `Disabled` 是“禁用”，云端记录的 `Do not upload`
是“不上传”。译文必须保留默认受限账户、显式高权限确认、不确定状态以及
删除操作的完整影响范围。

用户名称、标识、命令、凭据与日志保留原文。使用 `data-no-i18n` 或
`translate="no"` 标记这些数据，元素属性也会保留。脚本、样式、代码、预格式化文本、
文本框、SVG、机器错误码、表单值、请求参数、命令选项和权限位保持原字节，
翻译它们周围的标签和状态说明。

## 回归验证

既有词库测试检查唯一键、只读映射、模板语言和管理员错误文案；Worker
语言测试覆盖注册模式、文本分块与实体、语言选择、数据保护和关键语义。

更新呈现基准时，除可见文字外，还应检查数据保护和无障碍标记。除非明确修改命令约定，否则应保持复制出的注册命令不变。

在本地隔离实例运行界面与浏览器集成测试，检查两种语言的含义、排版和无障碍标签。
随后按正常 Worker 部署流程核对线上页面。
