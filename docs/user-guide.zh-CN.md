# 用户指南

Runmesh 让兼容 MCP 的 AI 客户端安全使用管理员批准的电脑和工作区。本指南面向实际使用者，不要求了解 Cloudflare、Node.js 或项目源代码。

## 你需要什么

- 管理员提供的完整 MCP 地址；
- 一个支持 Streamable HTTP 的 MCP 客户端；
- 管理员已经为你的客户端开放至少一台 Runner 和一个工作区。

MCP 地址是一项秘密凭据，只在创建或轮换时显示一次。请像保护密码一样保存它。

## 连接客户端

在客户端的 MCP 设置中添加管理员提供的完整地址：

```text
https://你的域名/一次性生成的密钥/mcp
```

不要自行修改地址，不要再添加 Bearer token。若客户端提示无法连接，先确认地址完整、没有换行或多余空格，再联系管理员。

## 第一次操作

连接成功后按以下顺序使用：

1. `runner_list`：查看可用机器及在线状态。
2. `runner_select`：有多台机器时选择目标；切换已选机器需要 `confirm_switch: true`。
3. `runner_current`：确认当前选择。
4. `workspace_list`：查看可用工作区及权限。
5. `read` 或 `inspect`：先查看文件、目录和 Git 状态。

工作区名称是管理员定义的标识，不等于电脑上的真实路径。真实路径不会通过 MCP 返回。

## 修改文件

需要修改时使用 `edit`。先让客户端读取目标文件，再提交带有当前内容基线的修改。若文件在你查看后被别人改动，Runmesh 会拒绝覆盖并要求重新读取，避免误覆盖。

修改失败时，Runmesh 会保留原文件并返回可处理的错误。不要通过 `shell` 绕过工作区权限。

## 执行命令与任务

`shell` 会以 Runner 服务账号的权限启动命令。它不是沙箱：命令可能访问该账号本来就能访问的文件、网络、环境变量和进程。

长时间工作请使用后台模式，并用 `job`：

- `job` 的 `list` 查看任务；
- `job` 的 `get` 查看状态；
- `job` 的 `logs` 分页读取输出；
- `job` 的 `input` 发送输入；
- `job` 的 `cancel` 请求取消。

浏览器关闭、MCP 请求结束或 Runner 短暂断线，不会自动停止已经启动的持久任务。日志有大小上限，出现 `output_truncated` 时应在机器本地检查完整日志。

## 常见提示

- **没有可用 Runner**：请联系管理员检查机器是否开机、服务是否在线，以及你的客户端是否被授权。
- **权限不足**：请求管理员为对应客户端、Runner 和工作区同时开放所需能力。
- **Runner 离线**：Runmesh 不会静默切换到另一台机器。管理员恢复原 Runner 后再重试，或明确选择另一台机器。
- **凭据失效**：管理员需要轮换 MCP 客户端并向你发送新的地址。旧地址不能恢复。

## 使用安全建议

不要让高权限 Runner 执行不受信任的仓库或脚本。不要在对话、截图、工单、Shell 历史或代码中粘贴 MCP 地址、注册码或 Runner 凭据。发现泄露时立即通知管理员轮换或撤销。
