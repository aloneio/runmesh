# CLA 签署与记录流程

Runmesh 以 Harmony 风格的许可授权模式为基础制定个人和实体贡献者协议。除非本文件以
仓库证据更新，否则项目不会声称已经配置 CLA Assistant 或其他自动化服务。

## 使用哪份协议？

- 如果你仅以个人身份贡献，请使用 [CLA-INDIVIDUAL.md](../../CLA-INDIVIDUAL.md)。
- 如果公司、机构或其他实体拥有或控制贡献内容，或你代表实体提交，请使用 [CLA-ENTITY.md](../../CLA-ENTITY.md)。

两份协议都是许可授权，不是版权转让。贡献者和实体保留版权及署名；授权允许项目将已接收
的贡献纳入当前源码可见社区版以及未来获得商业许可的 Runmesh 版本，但不会授予贡献者或
实体商业使用权。

## 维护者流程

在尚未明确配置自动签署前，维护者应：

1. 请贡献者阅读适用协议，确认其有权授予协议中的权利；
2. 收到签署副本、可验证电子签名或书面接受，且能识别协议版本和贡献范围；
3. 对实体贡献确认签署人有权代表实体，并保留授权贡献者名单；
4. 将协议保存在受限的贡献记录系统，不要把签名、个人地址、私密邮箱或身份证明提交到
   公开仓库；
5. 将记录关联到 pull request，只保留最小状态，例如 `CLA-INDIVIDUAL v1 accepted`；
6. 在 Git 和项目致谢中保留贡献者署名。

协议记录完成前可以讨论 pull request，但实质代码不应作为已接收贡献合并。文档、issue
讨论和小型非代码反馈可由维护者根据情况处理。

## 可选自动化配置

如果未来通过仓库管理权限启用 CLA Assistant 或其他同类服务，应在此记录具体服务商、仓库
配置、协议 URL、Webhook/App 权限、隐私行为和测试 pull request。在维护者验证前，不要加入
状态徽章，也不要告知贡献者自动化已启用。

本文件是操作指引，不是法律意见，也不表示协议已经过律师审查。
